## 1. 开发环境准备

### 1.1 必装工具

| 工具 | 版本 | 说明 |
| --- | --- | --- |
| JDK | **21** | 强制要求，所有 Java 服务 |
| Maven | 3.8+ | 无 wrapper，需系统安装 |
| Node.js | 18+ | 前端开发 |
| Git | — | 版本控制 |
| MySQL | 8+ | 本地开发或使用 Docker |
| Redis | 6+ | 本地开发或使用 Docker |
| Nacos | 2.x+ | 本地开发或使用 Docker |
| IDE | IntelliJ IDEA | 推荐 |

### 1.2 首次运行步骤

```bash
# 1. 克隆仓库
git clone <repo-url>
cd java-backend

# 2. 启动基础设施（推荐用 Docker 只起中间件）
docker compose up -d mysql redis nacos

# 3. 初始化数据库（首次）
mysql -h127.0.0.1 -P3307 -uroot -p example_db < sql/init.sql

# 4. 构建根工程
mvn clean package -DskipTests

# 5. 启动三个后端服务（三个终端）
mvn -pl system-service spring-boot:run
mvn -pl business-service spring-boot:run
mvn -pl gateway spring-boot:run

# 6. 启动 javachain（独立工程，注意 cd）
cd javachain && mvn spring-boot:run

# 7. 启动前端
cd oa-frontend && npm install && npm run dev
```

访问 `http://localhost:5173`。

### 1.3 IDE 配置要点

| 项 | 配置 |

| 语言级别 | 21 |
| Lombok | 安装插件并启用注解处理 |

## 2. 项目结构与模块边界

```text
java-backend/
├── pom.xml                 # 根 POM（聚合 gateway / system-service / business-service）
├── gateway/                # 网关模块
├── system-service/         # 系统服务模块
├── business-service/       # 业务服务模块
├── javachain/              # ⚠️ 独立 Maven 工程（有自己的 pom.xml，无 parent）
├── oa-frontend/            # 前端工程
├── sql/                    # 数据库脚本
├── docker/                 # Dockerfile
├── docs/                   # 项目文档
└── docker-compose.yml
```

### 2.1 模块边界规则

| 规则 | 说明 |
| --- | --- |
| **javachain 独立构建** | 必须在 `javachain/` 目录下执行 Maven 命令，不能通过根 POM 构建 |
| **不引入公共库模块** | 各服务独立演进，`Result`、`JwtUtil` 等类按服务复制，不抽公共库 |
| **服务间调用走 Feign** | 不直接跨服务访问数据库 |
| **前端只调网关** | 不直连后端服务端口 |

> ⚠️ 关于"同名副本类"：`Result.java`、`JwtUtil.java`、`DashboardStats.java`、`PageResponse.java` 在多个模块中重复存在，这是**有意的设计**（ADR-06），不要擅自合并。修改时需**同步所有副本**。

## 3. 后端开发规范

### 3.1 分层结构

```text
controller → service（接口）→ service.impl（实现）→ mapper → MySQL
                    ↓
              entity / dto / vo
```

| 层 | 职责 | 禁止 |
| --- | --- | --- |
| `controller` | 参数接收、响应封装 | 不写业务逻辑 |
| `service` | 业务逻辑、事务 | 不直接操作 HttpServletRequest |
| `mapper` | 数据访问 | 不写业务判断 |
| `entity` | 数据库实体 | 不暴露给前端（用 dto/vo） |
| `dto` | 入参对象 | — |
| `vo` | 出参对象 | — |

### 3.2 包结构规范

```text
com.oa.<service>/
├── common/       # 统一返回、常量
├── config/       # 配置类
├── controller/   # 控制器
├── dto/          # 入参 DTO
├── entity/       # 实体
├── enums/        # 枚举
├── exception/    # 异常
├── feign/        # 服务调用
├── mapper/       # MyBatis Mapper
├── service/      # 服务接口
│   └── impl/     # 服务实现
└── util/         # 工具类
```

javachain 使用 `com.example.javachain` 包名（历史遗留，与其他服务不同）。

### 3.3 命名规范

| 类型 | 规范 | 示例 |
| --- | --- | --- |
| 类名 | 大驼峰 | `UserServiceImpl` |
| 方法名 | 小驼峰 | `getUserById` |
| 常量 | 全大写下划线 | `MAX_RESULTS` |
| 包名 | 全小写 | `com.oa.system.controller` |
| 数据库表 | 下划线，系统表前缀 `sys_` | `sys_user` |
| 数据库字段 | 下划线 | `create_time` |
| REST 路径 | 小写，资源复数 | `/system/users` |

> Java 字段用驼峰，数据库用下划线，由 MyBatis 的 `map-underscore-to-camel-case: true` 自动映射。

### 3.4 统一返回规范

使用各模块的 `Result<T>`：

```java
// 成功
return Result.success(data);
return Result.success("操作成功", data);

// 失败
return Result.error("错误信息");
return Result.error(401, "未认证");
```

javachain 使用 `ApiResult<T>`（多一个 `success` 字段）。

**规范**：

- `code = 200` 表示成功，其他为失败
- `message` 为**面向用户**的中文提示
- 业务数据放 `data`，不塞进 `message`

### 3.5 异常处理

```java
// 业务异常
throw new BusinessException("用户不存在");

// Controller 内捕获并转换（现有风格）
try {
    // ...
} catch (Exception e) {
    log.error("操作失败", e);
    return Result.error(500, e.getMessage());
}
```

| 场景 | code |
| --- | --- |
| 成功 | 200 |
| 未认证 | 401 |
| 无权限 | 403 |
| 业务错误 | 500 |
| 资源不存在 | 404 |

### 3.6 接口开发规范

**新增接口检查清单**：

- [ ] 确认 controller 路径前缀与网关重写规则匹配
  - system-service → `/system/**`
  - business-service → `/business/**`
  - javachain → `/api/**`
- [ ] 使用统一的 `Result` / `ApiResult` 封装
- [ ] 入参使用 DTO，出参使用 VO 或实体
- [ ] 写操作记录操作人（从请求头 `userId` 获取）
- [ ] 敏感操作添加权限校验
- [ ] 关键接口添加 `@ApiLog` 日志注解（business-service）

**从请求头获取当前用户**（网关注入）：

```java
@PostMapping
public Result<Void> create(@RequestBody XxxRequest request,
                           @RequestHeader(value = "userId", required = false) String userIdStr) {
    Long userId = userIdStr != null ? Long.parseLong(userIdStr) : 1L;
    // ...
}
```

> 注意：现有代码在 `userId` 缺失时**默认取 1**，这是一个隐患。新代码建议显式校验。

### 3.7 MyBatis 规范

| 项 | 规范 |
| --- | --- |
| Mapper 位置 | `src/main/resources/mapper/*.xml` |
| 驼峰映射 | 已开启 `map-underscore-to-camel-case` |
| SQL 日志 | 开发环境开启，**生产环境应关闭** |
| 参数 | 使用 `#{}` 防止 SQL 注入，禁止 `${}` 拼接用户输入 |
| 分页 | 现有代码在内存分页，新接口建议用 SQL `LIMIT` |

### 3.8 日志规范

```java
private static final Logger log = LoggerFactory.getLogger(XxxController.class);

log.info("查询用户: userId={}", userId);       // 关键业务节点
log.warn("Token 校验失败: {}", path);          // 可恢复的异常
log.error("操作失败", e);                      // 异常，带堆栈
```

| 规范 | 说明 |
| --- | --- |
| 使用占位符 | `log.info("x={}", x)` 不要字符串拼接 |
| 异常带堆栈 | `log.error("msg", e)` |
| 不打印敏感信息 | 密码、Token、密钥 |
| 分级合理 | 高频日志用 `debug` |

### 3.9 注释规范

- 类、公开方法必须有 Javadoc
- 复杂业务逻辑必须有行内注释说明**为什么**
- 现有中文注释风格延续

```java
/**
 * 执行自主推理任务
 *
 * @param userQuestion 用户问题
 * @return 推理结果
 */
public ReasoningResult execute(String userQuestion) { ... }
```

## 4. javachain 开发规范

### 4.1 新增本地工具

在 `SkillService` 中添加 `@Tool` 注解方法：

```java
@Tool("工具描述，参数：param1(说明), param2(说明)")
public String myTool(String param1, int param2) {
    // 实现
    return "结果字符串";
}
```

**要求**：

- 返回值统一为 `String`（MCP 协议要求）
- 参数类型受支持：`String`、数值、`boolean`、`Map`、`List`
- 错误时返回**错误描述字符串**而非抛异常（Agent 会据此判断）
- `@Value` 字段描述中的参数说明会进入提示词，必须写清楚

### 4.2 新增 Skill

1. 在 `javachain/src/main/resources/.trae/skills/` 下新建目录
2. 目录名即技能名
3. 新建 `SKILL.md`，遵循 `SkillParser` 可解析的格式（含触发词、步骤）
4. 构建时会被自动打包（`pom.xml` 中 `<include>**/.*</include>` 保证隐藏目录被打包）
5. 运行时可通过重载接口热更新

### 4.3 修改 Agent 行为

| 需调整 | 修改位置 |
| --- | --- |
| 步数/超时/重试等限制 | `ReActAgentConfig`（`javachain.agent.*`） |
| 提示词模板 | `ReActAgent.buildSystemPrompt()` |
| 输出解析规则 | `ReActAgent.parseStep()` 正则 |
| 敏感词 | `ReActAgentConfig.sensitiveKeywords` |
| 危险工具 | `ReActAgentConfig.dangerousTools` |
| 结果有效性判断 | `ReActAgent.isObservationUseful()` |

> ⚠️ 修改提示词模板时，必须同步检查 `parseStep()` 的正则是否能匹配新格式。

### 4.4 更换向量库

替换 `VectorStoreConfig` 中的 `EmbeddingStore<TextSegment>` Bean 即可。当前为内存实现，生产环境需替换为持久化实现。

## 5. 前端开发规范

### 5.1 目录职责

| 目录 | 职责 |
| --- | --- |
| `src/api/` | 按业务域拆分接口调用，一个模块一个文件 |
| `src/views/` | 页面组件 |
| `src/router/` | 路由配置与守卫 |
| `src/stores/` | Pinia 状态管理 |
| `src/utils/` | 工具与请求封装 |
| `src/directives/` | 自定义指令 |

### 5.2 新增页面流程

1. 在 `src/views/` 创建页面组件
2. 在 `src/router/index.js` 注册路由（放在 `Layout.vue` 的 children 下）
3. 在数据库 `sys_menu` 表添加菜单记录（含 `path`、`component`、`role_keys`）
4. 如需后端接口，在 `src/api/` 添加对应封装

> ⚠️ 路由的 `path` 必须与 `sys_menu.path` 完全一致，否则菜单点击无法跳转。

### 5.3 API 封装规范

```javascript
// src/api/product.js
import request from '@/utils/request'

export function getProducts(params) {
  return request({ url: '/business/products', method: 'get', params })
}

export function createProduct(data) {
  return request({ url: '/business/products', method: 'post', data })
}
```

**规范**：

- 统一使用 `@/utils/request`，不要直接用 axios
- `baseURL` 已配置为 `/api`，写路径时**不要再加 `/api` 前缀**
- 路径中的服务前缀要与网关路由一致：`/system/**`、`/business/**`、`/javachain/**`

### 5.4 响应处理

`request.js` 的响应拦截器已处理：

- 自动解包，返回 `res`（即 `{ code, message, data }`）
- `code !== 200` 自动弹错误提示
- 401 自动跳登录页
- 502/503 自动跳维护页

因此**业务代码只需处理成功逻辑**：

```javascript
const res = await getProducts({ pageNum: 1, pageSize: 10 })
this.list = res.data.records
```

### 5.5 组件规范

| 项 | 规范 |
| --- | --- |
| 组件命名 | 大驼峰，文件名与组件名一致（`UserManagement.vue`） |
| 组合式 API | 使用 `<script setup>` |
| 样式 | scoped |
| UI 库 | 统一使用 Element Plus |
| 别名 | 使用 `@` 指向 `src` |

### 5.6 权限控制

使用权限指令（`src/directives/permission.js`）：

```vue
<el-button v-permission="'role:manage'">新增角色</el-button>
```

## 6. 配置管理规范

### 6.1 敏感信息处理原则

> ⚠️ **当前项目存在严重的密钥管理问题**：密钥硬编码在 `application.yml`、`.env`、`docker-compose.yml` 中且已提交到仓库。

**新代码必须遵守**：

| 规则 | 说明 |
| --- | --- |
| 密钥用环境变量 | 格式：`${ENV_NAME:默认值}` |
| 默认值保持占位 | 默认值用 `your_password` 等占位符，不写真实值 |
| `.env` 不入库 | 确认 `.gitignore` 生效 |
| 文档用占位符 | 文档中示例不写真实密钥 |
| 提交前自查 | `git diff` 检查是否带入了密钥 |

### 6.2 配置项命名

```yaml
# 服务自定义配置用服务名前缀
javachain:
  llm:
    provider: ${JAVACHAIN_LLM_PROVIDER:deepseek}

mybatis:
  mapper-locations: classpath:mapper/*.xml
```

### 6.3 环境变量命名

统一 `大写下划线`，与配置项对应：

| 配置 | 环境变量 |

## 10. 常见开发陷阱

| 陷阱 | 说明 | 规避 |
| --- | --- | --- |
| javachain 未单独构建 | 根 POM 不包含 javachain | `cd javachain` 后构建 |
| JWT 密钥不一致 | 四服务需同步修改 | 改 `jwt.secret` 时四处同改 |
| 路径前缀错误 | 三服务前缀各不相同 | system→`/system`、business→`/business`、javachain→`/api` |
| 端口混淆 | 宿主机与容器端口不同 | 宿主机连 MySQL 用 3307 |
| 修改副本类遗漏 | 同名类存在多份 | 全局搜索确认所有副本 |
| 前端路径重复 | `baseURL` 已含 `/api` | 封装里写 `/business/xxx` |
| 内存分页性能 | 现有实现先查全表 | 新接口用 SQL `LIMIT` |
| 知识库数据丢失 | 内存存储 | 重启后需重新向量化 |
| 菜单不显示 | `role_keys` 不匹配 | 确认角色 `role_key` 值 |
| 硬编码路径 | 如文件向量化目录 | 改为配置项 |
