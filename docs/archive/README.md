# 历史版本归档

本目录存放**已归档的历史版本文档**。

> ⚠️ **本目录下的所有文件均已冻结，不再维护。**
> 请勿修改归档文件。如需查看最新版本，请前往各文档的正文目录。

---

## 归档规则速览

| 项 | 规则 |
| --- | --- |
| 为何归档 | 保留历史基线，便于追溯"某功能是什么时候、为什么变成现在这样" |
| 归档时机 | **Issue 评审通过后、修改正文之前** |
| 归档什么 | **仅归档本次将修改的文档**，不要全量复制 |
| 命名格式 | `<文档简称>-v<版本>.md`，如 `PRD-v1.0.md` |
| 必备动作 | 归档文件头部标注"历史版本"、本文件登记索引 |

> ⚠️ **顺序不能反**：必须先归档、再改正文。改完再归档，存的是新版，历史基线就丢了。

**操作命令**：

```bash
# 以 PRD 为例：当前 v1.0，即将升级为 v1.1
cp docs/01-产品/PRD-产品需求文档.md docs/archive/PRD-v1.0.md
# 然后编辑归档文件头部添加"历史版本"标注
# 再修改正文，升版本号为 v1.1
```

**归档文件头部标注格式**：

```markdown
> ⚠️ **历史版本归档**
> 本文件为 PRD 的 v1.0 版本，已归档，**不再维护**。
> 最新版本见 [docs/01-产品/PRD-产品需求文档.md](../01-产品/PRD-产品需求文档.md)
>
> 归档日期：2026-10-10
> 归档原因：商品管理新增供应商字段（#12）
```

## 与 Git 历史的关系

| 方式 | 面向对象 | 优点 | 缺点 |
| --- | --- | --- | --- |
| Git 历史 | 机器 / 熟悉 Git 的人 | 完整、无额外成本 | 需会 `git show`，非技术同学看不懂 |
| 本目录归档 | 所有人 | 任何人可读、一目了然 | 有文件冗余 |

**结论**：两者都要，互为补充。归档面向"人"，Git 面向"机器"。
